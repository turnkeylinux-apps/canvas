## Source and dependency decision

Debian does not package Canvas LMS. The appliance therefore installs the
official Canvas production release identified by the `prod` branch at commit
`44bfdc264d5fe6a942ebdb5f10a0eb63ee04df3a`, whose source tree is
`dd2a9caa6afe683108a493a13c32340e1b3ac5e6`. The downloaded commit archive
must match SHA256
`2ca116f8a130b970c7b945fd547e760bdb8e7b8d0ea4c1c63f07222fd874009c`.
The commit is the official production merge for stable release 2026-04-22.

The official RCE API is pinned to commit
`e076fe28a09f4e41058da0983b5ef2c809123d9f`, tree
`4a2e99c1efccf0011215bb074065a0859135a132` and archive SHA256
`1b36c2231c09d406053c92fde9d805211e538265e8d01827477a3ce9187c0495`.

Current Canvas requires Ruby 3.4.1 or newer within Ruby 3.4 and Node.js 20.
The inherited TurnKey Rails build installs Ruby 3.4 through its maintained
ruby-build path. Debian Trixie supplies Node.js 20, PostgreSQL, Redis and the
native build libraries. Debian's `yarnpkg` is Yarn 4.1 and does not satisfy the
Canvas Yarn Classic lock and install contract. The inherited Rails build
therefore installs Yarn Classic from Yarn's signed official APT channel. The
acceptance test refreshes only that source and requires a valid package
candidate. Bundler 2.6.7 and all Ruby, JavaScript and RCE dependencies remain
locked by the official source trees.

## Update contract

`turnkey-canvas-update --check` identifies the installed release and resolves
the official Canvas `prod` and RCE `master` heads to their exact commits and
trees. `--apply --dry-run` reports the same targets without changing the
appliance. A supervised `--apply` creates PostgreSQL and generated-file
backups, verifies fetched Git objects against both eligible trees, preserves
Canvas YAML configuration, local files and RCE secrets, then follows the
upstream bundle, Yarn, asset, migration and notification update sequence.

## Deferred issues

- MEDIUM: Upstream recommends at least 8 GB RAM for production asset
  compilation. Small systems can run Canvas after assets are built, but an
  administrator should provision update-time memory according to the upstream
  production guidance.
- MEDIUM: The official RCE project publishes its maintained code on `master`
  between version tags. The appliance pins an exact commit and tree and exposes
  any newer official branch head through the supervised updater.

## Loop accounting

Product loops begin at zero. Only a reproduced main-flow appliance defect or a
HIGH issue reachable in a normal supported deployment consumes the three-loop
ceiling. Source checks, test corrections, builder queue failures, retained
evidence updates and the known shared cleanup dependency failure consume zero
product loops.
